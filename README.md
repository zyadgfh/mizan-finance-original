# ميزان المالية — Mizan Finance (v2.0)

منصة إدارة مالية شخصية وعائلية وتجارية متعددة المساحات (**Offline-First Multi-Tenant Personal & Business Finance Platform**) تدعم العربية والإنجليزية بالكامل (`RTL` / `LTR`) وتعمل عبر الويب وتطبيق أندرويد أصلي (`APK`).

## أبرز المميزات | Key Capabilities

1. **إدارة حسابات حصرية للمالك (Owner-Only Provisioning):**
   - التسجيل العام مغلق بالكامل على مستوى واجهة المستخدم وخادم المصادقة (`Supabase Auth`).
   - مالك المنصة فقط (`Super-Admin`) ينشئ حسابات المستخدمين الجدد، يولّد كلمات المرور المؤقتة أو يرسل روابط التعيين، ويتحكم في تفعيل وإيقاف المساحات والاشتراكات من لوحة `/admin`.
2. **تعدد المساحات والعمل بدون إنترنت (Offline-First Multi-Tenancy):**
   - تخزين محلي فوري عبر `IndexedDB` مع طابور مزامنة ذكي يرفع التعديلات تلقائياً إلى `Supabase Postgres` فور عودة الاتصال.
3. **مزامنة سحابية مشفرة للإيصالات والفواتير (Cloud Receipt Sync):**
   - ضغط الصور على الجهاز ورفعها تلقائياً إلى سلة خاصة (`mizan-receipts`) معزولة بسياسات `RLS` لكل مساحة عمل (`{tenant_id}/{receipt_id}`).
4. **بوابة تأكيد وموافقات الدفع اليدوي (InstaPay / Vodafone Cash):**
   - إرسال طلبات تجديد الاشتراك مرفقة بصورة التحويل ورقم المرجع ومراجعتها واعتمادها بضغطة واحدة من لوحة المالك.
5. **تعدد العملات والتحليلات الذكية والخصوصية:**
   - تجميد سعر الصرف التاريخي لكل معاملة، قفل التطبيق برمز `PIN` أو البصمة البيومترية (`WebAuthn`), وتصدير/استيراد النسخ الاحتياطية المشفرة (`AES-GCM 256-bit`) وملفات `CSV`.

## القيود المعروفة | Known Limitations

موثّقة صراحةً حتى لا يُفهم من المميزات أعلاه أكثر مما هو منفّذ فعلياً:

1. **لا يوجد تشفير من الطرف إلى الطرف (No E2EE) لسجلات المزامنة السحابية:**
   النقل مؤمَّن بـ `TLS` والوصول محكوم بسياسات `RLS` لكل مساحة عمل، لكن قواعد البيانات
   السحابية (`Supabase Postgres`) تستطيع قراءة محتوى جدول `tenant_records`، وكذلك
   سجلات التدقيق. التشفير الفعلي (`AES-GCM 256-bit`) مقتصر على النسخ الاحتياطية
   المحلية المُصدَّرة، ولا تدّعي الواجهة تشفيراً طرفياً.
2. **التحقق من البيانات عند حدّ المزامنة:**
   كل سجل يُرفع يمر الآن على مخطط كامل لكل كيان (أنواع الحقول والقيم المسموحة) على
   العميل (`src/lib/tenant/entity-payloads.ts`) وعلى الخادم
   (`public.tenant_payload_error` داخل `sync_push_tenant_records`)، ويُرفض بكود
   `INVALID_PAYLOAD` بدل تخزينه. التشديد على حقول المعرّفات فقط (لا يجوز أن تكون فارغة)
   أما النصوص الحرة فتُفحص كنوع فقط وقد تكون فارغة عمداً، والقيم المغلقة الاختيارية
   الفارغة تُعدّ «غير مضبوطة».
   وينطبق الشيء نفسه على السحب: أي سجل قادم من الخادم لا يجتاز المخطط، أو معرّفه لا
   يطابق المفتاح المخزَّن به، يُبلَّغ بكود `INVALID_REMOTE_PAYLOAD` ولا يُدمج في النسخة
   المحلية (والخادم نفسه يرفض الآن رفع سجل مفتاحه لا يطابق معرّفه). ما **لا** يغطيه ذلك:
   حقول الميتاداتا (`createdBy`, `updatedAt`) لا تُفحص قيمها، والفحص يصف **الشكل** لا
   الصحة التجارية (مبلغ سالب، أو تاريخ في المستقبل، يمر).
3. **جسر أندرويد (Capacitor) كما هو:**
   لم يُستبدل `WebViewClient` / `BridgeActivity` الافتراضي — أي تعديل عليه قد يكسر
   جسر الإضافات الأصلية (الإشعارات المحلية). الحماية تعتمد على سياسة الشبكة في
   `AndroidManifest.xml` وقصر التحميل على HTTPS، لا على اعتراض الطلبات داخل الويب فيو.

## التشغيل المحلي والاختبار | Local Development

```bash
# تثبيت الحزم
npm ci

# تشغيل خادم التطوير المحلي (المنفذ 8080)
npm run dev

# فحص الأنواع وجودة الكود والاختبارات
npm run typecheck
npm run lint
npm test

# بناء نسخة الإنتاج للويب
npm run build

# بناء ومزامنة حزمة الأندرويد (Capacitor)
npm run cap:sync
```
